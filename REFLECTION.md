# Version Control Project Reflection

In this project, I practiced using Git and GitHub to manage a realistic version control workflow. I began by creating an empty GitHub repository named `version-control-simulation-franky-ndalle`. I cloned the repository to my local computer and opened it in Visual Studio Code. I then created the `feature/header` branch with `git checkout -b feature/header`. On that branch, I created `index.html`, added the basic HTML structure and header content, staged the file, and committed it with a descriptive commit message.

Next, I switched to the `main` branch and created another branch named `feature/footer`. On this branch, I added footer content to `index.html` and committed that change. To simulate two developers editing the same part of a project, I returned to `feature/header`, changed the footer differently, and committed the update. These independent changes prepared the repository for a merge conflict.

I switched back to `main` and merged `feature/footer`. That merge completed successfully. When I attempted to merge `feature/header`, Git detected that both branches had changed the same footer lines and stopped the merge. Visual Studio Code displayed the current and incoming changes along with Git’s conflict markers. I resolved the conflict by accepting both useful changes, removing the conflict markers, saving the file, and staging it with `git add index.html`. I used `git status` to confirm that all conflicts were fixed and then committed the resolved merge.

Finally, I pushed `main`, `feature/header`, `feature/footer`, and `review/main` to GitHub. I created a pull request from `main` into `review/main` and included a detailed description of the changes. The pull request process supports code quality because reviewers can examine commits, compare file changes, discuss improvements, and approve or request changes before merging. This project showed me how branches, meaningful commits, conflict resolution, and pull requests help developers collaborate without losing one another’s work.
